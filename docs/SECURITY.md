# Security

## Principles

- **Files never leave the browser** during normal processing: Canvas, Web Workers (image, PDF, regex), pdf-lib, PDF.js, JSZip run locally. No upload endpoint exists.
- **Only the public anon key** reaches the browser. The service_role/secret key is never used; `assertNotServiceRole` refuses one at runtime and a test scans `src/` for secrets.
- **Authorization lives in PostgreSQL (RLS)**, not in the UI.

## Database policies (summary)

| Table | anon / visitor | editor | admin | owner |
| --- | --- | --- | --- | --- |
| tools | read published, not archived | read all, insert, update | + delete archived | same |
| categories | read visible | read, update | + insert, delete (FK restrict) | same |
| pages, faqs, translations, announcements | read published/active | full CRUD (pages delete: admin) | ✓ | ✓ |
| homepage_sections | read | update | + insert | ✓ |
| site_settings | read (public, non-secret only) | — | insert/update | ✓ |
| advertisement_slots | read enabled | — | insert/update | ✓ |
| admin_users | — | read own row | read all | changes only via `set_admin_role()` / `remove_admin()` |
| admin_activity_logs | — | — | read | read |

- `current_admin_role()` / `has_admin_role()` are `SECURITY DEFINER` with `search_path = ''`.
- No direct write policy on `admin_users`; `set_admin_role` is owner-only, cannot target self, and a deferred trigger keeps at least one active owner. **Admins cannot grant themselves privileges.**
- Activity logs are inserted by an `AFTER` trigger (`audit_row`) and `log_admin_event()` (allow-listed actions). They record changed column names and status/role transitions — never passwords, tokens or page content.
- CHECK constraints validate slugs, lengths, URLs, enums and implementation keys (mirrored client-side).
- `public_site_payload()` is `SECURITY INVOKER` and filters published rows explicitly.

## Web security

- **CSP** generated by Astro with SHA-256 hashes for scripts and `<style>`; `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `connect-src` limited to self + your Supabase origin. `style="…"` attributes are allowed (dynamic widths/colors in React).
- Headers (middleware): `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, `COOP`, HSTS on HTTPS; `/admin` and `/api` get `X-Robots-Tag: noindex` and `/admin` `Cache-Control: no-store`.
- **No arbitrary HTML/JS**: admin Markdown is rendered with raw HTML escaped and URLs filtered (`renderSafeMarkdown`); the Markdown previewer tool uses DOMPurify; SVG is sanitized (DOMPurify + filters) and rendered as an image; JSON-LD is escaped.
- **CSRF**: the app has no cookie-authenticated endpoints (Supabase uses bearer tokens in headers); Astro `checkOrigin` is on for any form POST.
- **Rate limiting**: Supabase Auth enforces server-side limits; the login form adds progressive client-side delays and generic error messages (no account enumeration). Password reset always returns the same message.
- **File handling**: signature-based type detection, size limits, sanitized download names, object URLs revoked, workers terminated when idle, canvas size limits.
- **Regex DoS**: user regexes run in a worker killed after 1.5 s.
- **JWT decoder** explicitly does not verify signatures. Encrypted PDFs are never bypassed.
